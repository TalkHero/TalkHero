# TalkHero Design System

**Version:** 1.0  
**Status:** Release Candidate 1

## Purpose

TalkHero Design System визначає єдині правила побудови інтерфейсу. Нові екрани мають використовувати спільні токени й компоненти, а не створювати окремий візуальний стиль.

## Principles

### Simple before smart

Спочатку інтерфейс має бути зрозумілим. Технологія та AI не повинні ускладнювати основну дію.

### One primary action

На одному екрані має бути одна очевидна головна дія.

### Consistency beats decoration

Однакові компоненти, відступи та стани важливіші за випадкові декоративні рішення.

### Whitespace is interface

Вільний простір допомагає користувачу бачити структуру та фокусуватися на завданні.

### Mobile first

Кожен основний сценарій повинен працювати на ширині від 360 px.

## Shadows

Використовуються лише три рівні:

- `shadow-sm` — звичайні картки;
- `shadow-md` — інтерактивні та підняті картки;
- `shadow-lg` — модальні вікна.

## Typography

- Font family: Inter.
- Основний текст: не менше `16 px`.
- Допоміжний текст: не менше `14 px`.
- Кнопки: medium або semibold.
- Заголовки: semibold або bold.
- Довгі тексти не використовують надто широку колонку.

## Components

### Button

- мінімальна висота `48 px`;
- чіткий focus-visible;
- стани default, hover, active, disabled, loading;
- варіанти primary, secondary, outline, ghost, danger.

### Card

- білий фон;
- нейтральна тонка рамка;
- радіус `18–24 px`;
- тінь лише за потреби;
- достатній внутрішній відступ.

### Input

- мінімальна висота `48 px`;
- радіус не менше `14 px`;
- видимий focus;
- зрозумілі error та disabled стани.

### Progress

- доступний текстовий підпис;
- плавна анімація;
- колір не є єдиним способом передати стан.

## Quest layout

Основний порядок:

1. Навігація і назва місії.
2. Прогрес.
3. NPC або контекст сцени.
4. Завдання.
5. Відповідь користувача.
6. Зворотний зв’язок.
7. Одна головна кнопка продовження.

## Mobile

Обов’язкові контрольні ширини:

- `360 px`;
- `390 px`;
- `430 px`;
- `768 px`.

Заборонена горизонтальна прокрутка основного інтерфейсу.

Інтерактивні елементи мають бути зручними для натискання пальцем.

## Motion

| Interaction         | Duration |
| ------------------- | -------- |
| Hover               | `150 ms` |
| Standard transition | `200 ms` |
| Modal and sheet     | `250 ms` |
| Toast               | `300 ms` |

Анімація не повинна блокувати виконання завдання.

Потрібно враховувати `prefers-reduced-motion`.

## Accessibility

- мінімальний рівень контрасту WCAG AA;
- видимий клавіатурний фокус;
- семантичні кнопки та поля;
- зрозумілі labels;
- мінімальна ціль натискання близько `44 × 44 px`;
- не покладатися лише на колір;
- підтримувати клавіатурну навігацію.

## Icons

В інтерфейсі використовується один набір — Lucide.

Emoji допустимі лише як частина навчального контенту, винагороди або емоційного повідомлення.

## Beta requirement

Користувач повинен без допомоги розробника:

1. зареєструватися;
2. знайти наступну навчальну дію;
3. розпочати місію;
4. завершити її;
5. зрозуміти результат;
6. повернутися до продовження навчання.
